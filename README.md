# AI Video Content Pipeline

複数のYouTubeチャンネルで本番稼働している、コンテンツ企画から投稿までを無人で回す自動化システム。台本の着想から公開後の振り返りまで、人間が介在しなくても回り続けることを前提に設計している。

## 概要

コンテンツの生産量がクリエイターの体力に直接張り付いている限り、チャンネルの成長は本人の可処分時間の関数でしかない。この系を切り離すには、企画・生成・審査・投稿・分析という一連の工程を、それぞれ独立したプロセスとして自動運転できる状態に落とし込む必要がある。本システムはその実装で、単発のスクリプトではなく「毎日動き続けて、失敗したら自分で気づいて止まる」ことを設計目標に置いている。

現在、フォーマットの異なる複数チャンネル(討論バラエティ形式、物理演算シミュレーションのショート動画形式など)がこの基盤の上で本番運用中で、うち1チャンネルは1日3本ペースの自動投稿を継続している。チャンネル固有の名称・URL・収益実績・視聴者データはポートフォリオとして公開する性質上ここには含めていないが、コード自体は実運用ログとリスク対策の試行錯誤を経た実装そのものである。

## パイプライン

1. **テーマ選定**: トレンド分析・競合チャンネル分析・季節イベント・ランダム性を担保する探索の4系統をスコアリングして候補を絞り込む多腕バンディット型のエンジン(`theme_pool.py`, `trend_theme_engine.py`, `competitor_theme_source.py`, `seasonal_theme_engine.py`, `wild_premise_engine.py`)
2. **台本生成**: Google Gemini APIでキャラクター設定・尺・構成ルールを反映した構造化JSON台本を生成(`generate_script.py`, `schema.py`)
3. **多層リスク審査**: 生成AI自身の自己審査に加え、NGワード辞書によるルールベース照合、個人情報検出、話題の偏り検知を独立したレイヤーとして直列に通す(`content_self_check.py`, `ng_word_filter.py`, `pii_filter.py`, `diversity_guard.py`)
4. **音声合成**: VOICEVOXでキャラクター別に音声を生成(`tts.py`)
5. **動画組み立て**: moviepy + OpenCVでキャラクター立ち絵・吹き出し・字幕・BGM/SEを合成(`assemble_video.py`)
6. **投稿**: YouTube Data APIで概要欄・タイトル・サムネイルを付けて自動アップロード(`youtube_upload.py`)
7. **分析**: YouTube Analytics APIから再生数・視聴維持率・エンゲージメントを収集(`collect_analytics.py`)
8. **改善ループ**: 収集した実績をもとにKPT(Keep/Problem/Try)を自動生成し、次回以降のテーマ選定・演出パラメータへフィードバックする(`generate_kpt.py`, `follow_up_kpt.py`, `weekly_content_sampling.py`)

全工程はGitHub Actionsのcronで駆動し、人が起動ボタンを押す前提を置いていない。

## フラッグシップ実装: 物理演算バトル形式

`geometry_battle_*.py` は、図形を物理演算(pymunk)で衝突・脱落させ、その結果をそのまま動画のドラマとして成立させるフォーマットの実装。ルール(ゴール到達/最終生存/陣取り等)、アリーナ形状、能力パラメータの組み合わせを大量に候補生成し、シミュレーション結果を「視聴継続に足る尺・意外性のある決着か」でスコアリングして採用可否を決める(`geometry_battle_idea_generator.py`, `geometry_battle_scoring.py`)。パラメータチューニングの試行錯誤はコード内コメントに実測ログとして残しており、「なぜこの値なのか」を後から追跡できるようにしている。

## 多層リスク対策

炎上・規約違反のリスクをゼロに近づけることを、収益化と同格の最優先事項として設計している。

- **ルールベース照合**: NGワード辞書による機械的なチェックを、生成AIの自己審査とは独立したレイヤーとして必ず通す(`ng_word_filter.py`)。単純な部分文字列一致は日常語との衝突(誤検知)を生むため、実際に発生した誤検知を都度学習する許可リストの仕組みを持つ
- **自己審査**: 生成した台本自体に、炎上リスク・著作権リスク・キャラクター設定からの逸脱がないかをAIに再評価させる(`content_self_check.py`)
- **PIIフィルタ**: 実在の個人情報が台本やコメント由来の企画に混入しないよう検出する(`pii_filter.py`)
- **多様性ガード**: 特定の属性・話題への偏りを検知し、テーマ選定を自動で分散させる(`diversity_guard.py`)
- **緊急停止**: 異常を検知した際にパイプライン自体を止める仕組み(`emergency_control.py`)
- **予算上限**: API利用額が月間上限を超えた時点で、全チャンネル共有でAI呼び出しを自動停止する仕組みも別途実装済み(本リポジトリには未収録)

## リポジトリの範囲について

本リポジトリは未踏アドバンスト事業への提出物として、実装の技術的な内容が伝わる範囲で公開している。以下は意図的に含めていない。

- チャンネル運用のインフラそのもの(GitHub Actionsのワークフロー定義、認証情報、Discord通知設定)
- キャラクター素材・BGM等のバイナリ資産、実際に投稿した台本・分析ログ
- NGワード辞書の実データ、チャンネル固有の運用ノウハウ文書

`scripts_templates/scripts/` には、台本JSONのスキーマを示すための架空のサンプルのみを置いている。

## 技術スタック

- 言語: Python
- 生成AI: Google Gemini API
- 音声合成: VOICEVOX
- 動画処理: moviepy, OpenCV, Pillow
- 物理演算: pymunk
- 投稿・分析: YouTube Data API, YouTube Analytics API
- インフラ: GitHub Actions(スケジューラ+matrixによるマルチチャンネル運用)
- 外部データ連携: Google Sheets API, Discord Webhook

詳細な設計は [`docs/architecture.md`](docs/architecture.md) を参照。
